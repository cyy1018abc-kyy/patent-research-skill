# 范围决策记录：软著联动与侵权分析（2026-10-25）

> 对应升级清单 P2-19。结论：**两者都不进默认路线**，记录理由与解冻条件，
> 避免每次讨论都从头论证。

## 决策 1：软著联动（对标 china-patent-software-copyright-skill）

**不做。** 理由：
1. 软著（计算机软件著作权登记）的产出物是源码材料与说明书文档，与专利检索的
   证据链（raw/工件、G-S 门）没有共享的数据结构——硬接会把两个域的校验搅在一起；
2. 本技能的证据分级对软著没有对应语义（登记不查新，无「在先技术」概念）；
3. 真要联动，正确的形态是**独立技能**共享 glossary，而非本技能加模块（见
   skill-matrix-plan.md 的拆分原则）。

**解冻条件**：出现「专利 + 软著双申请」的真实项目，且客户愿意提供软著材料结构样例。

## 决策 2：侵权分析（对标 PatentRadar）

**不做，且在 SKILL「不该用」表中明示。** 理由：
1. 侵权分析的方向与查新相反（拿自己的权利要求读别人的产品），判定责任等级完全
   不同——查新是自检底稿，侵权结论会直接驱动商业动作；
2. 需要 claims 构建特征对照（claim chart）+ **被诉产品技术特征分解**，后者本仓库
   完全没有数据结构；
3. patent-disclosure-skill 的 patent-chart 也是**独立技能**处理的，佐证了拆分而非合并。

**解冻条件**：有法务/代理师团队背书的专项需求；届时按独立技能立项（对照
patent-chart 的「不构成法律意见」边界）。
