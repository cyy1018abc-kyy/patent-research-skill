# NPL/标准资料源许可登记（License-First Gate）

- 状态：**v1（P1-B1 / 路线图 41B-1，2026-11-07 立）**。本文件是 NPL（非专利文献）与
  标准资料证据链的**许可先行门**：任何 NPL 全文上游，许可未在此核实登记前，代码面
  一律 `support_level=planned`、拒绝执行。
- 代码绑定：`extensions/patent_intel/src/patent_intel/sources/npl.py` 的
  `DOC_LICENSE_TABLE` 镜像本文 §4 登记总表；`require_licensed()` 按「未登记 /
  `support_level=planned` ⇒ 拒绝」执行。**改代码表与改本文档必须同一 commit**——
  两边漂移即门失效。
- 编写环境约束：本包在**离线环境**编写，未访问任何外部站点，未做任何新网络探测。
  因此除「仓库既有文档已记载许可状态」的源外（§3），一切新源只能登记为
  **未核实 → planned**（§4/§5）——本文档不编造、不臆测任何外部条款。

## 1. 门规则（对全部 NPL/标准全文上游生效）

1. **许可先于代码**：新增上游第一件事是在本文登记（逐源一节，§5 格式）；没有登记
   就没有注册行。
2. **未核实 = planned = 不可执行**：`support_level` 语义沿用
   `sources/base.py`（`full` 集成实测 / `partial` 契约测试未实测 / `planned`
   仅设计——必须不可执行）。许可状态未核实的源**最高只能 planned**，连 partial
   都不给：partial 意味着契约已验证可以跑，而许可门未过的源连跑的资格都没有。
   两层语义区分：**上游**（§4 表，`LicenseGrant.support_level`）与**适配器契约**
   （`sources/base.py` 的 `Capability.support_level`）是两回事——`npl` 适配器的
   采集契约可以是 `partial`（桩传输层契约已验证，与 OPS 同规则），但每个上游
   grant 都是 planned，`execute()` 在许可门就拒绝，所以契约验证过也跑不了任何
   真实采集。能力矩阵里 `npl | partial` 与本表全部 planned **不矛盾**。
3. **拒绝发生在任何传输层调用之前**：适配器 `execute()` 先过许可门再碰 transport；
   未许可源连一次网络调用都不允许发出。
4. **升级需要证据链**：planned → partial/full 必须同时具备（§6）：
   附录 A 风格的取证记录（日期 + 实测证据）+ `docs/policy-log.md` 接入事件登记 +
   `docs/architecture/source-capabilities.md` 镜像同步 + 本文与代码表同步。

## 3. 仓库既有文档已记载许可状态的源（照录，状态以原记录为准）

### 3.1 Crossref（书目元数据；既有登记，不因本包改动）

- **源**：Crossref Works API，经内核 `fetch-crossref` 命令（既有登记见
  `docs/architecture/source-capabilities.md`：`license_status=official_api`、
  `support_level=partial`）。
- **条款**：官方公开 API 的书目元数据检索；**逐字条款本仓库未核实**，既有登记口径
  以能力矩阵页为准，本文不新增许可断言。
- **再分发**：按仓库既有纪律——原始响应落 `02_search_logs/raw/`，raw 工件不入发行
  包；引用数字必须带检索日期。
- **正文获取**：**不适用**——该源是书目元数据通道，`npl.py` 的既有纪律（书目元数据
  ≠ 披露证据，UT-S04）明确：元数据记录永远不充当正文证据，正文不经此源获取。
- **结论**：元数据获取维持 `partial` 可执行（走内核契约）；NPL 正文链路**不**使用
  此源，也不因此源而豁免任何全文上游的许可门。

### 3.2 DAPFAM（检索评测语料；既有登记，照录）

- **许可**：CC-BY-NC-SA-4.0（数据集页实测确认，取证 2026-10-29，见
  `docs/retrieval-evaluation.md` 附录 A.1）。NC：语料与派生数据不入商业发行物；
  SA：派生数据集须同许可发布（当前决策：不发布任何派生数据集）；BY：引用须携带
  Ayaou et al., 2025（arXiv:2506.22141）与许可注记。
- **结论**：评测专用语料，不是 NPL 证据链的全文上游；不进入 `DOC_LICENSE_TABLE`，
  不受本门管辖（其分发边界由附录 A.1 原文约束）。

### 3.3 CLEF-IP（备选，未启用；既有登记，照录）

- **状态**：需注册申请，分发条款以届时官方文本为准；截至附录 A.2 记录日期
  **未申请、未下载、未使用**。
- **结论**：维持未启用；启用前属于本文 §4 的 planned 语义（许可未核实），即使走
  附录 A.2 的启用条件触发，仍须先补本文 §5 格式的登记。

## 5. 逐源登记（每源一节：源/条款/再分发/正文获取/结论）

### 5.1 arXiv

- **源**：arXiv.org（预印本服务器）。用途：预印本记录的元数据与预印本正文候选；
  与正式版的分离纪律由 `npl.py` 版本化正文承载（预印本记录与期刊记录是两条记录，
  引用其一不等于引用其二）。
- **条款**：**未核实**。本包离线环境未访问 arxiv.org；仓库既有文档无该源许可记载。
- **再分发**：未核实 ⇒ 默认**禁止**把任何抓取内容（元数据或正文）再分发进发行物；
  raw 工件只落本地 sidecar。
- **正文获取**：未核实 ⇒ planned，代码拒绝执行。
- **结论**：`support_level=planned`、不可执行。升级前置：§6 四件套 + 预印本↔正式版
  关系字段（`is-preprint-of` / `has-preprint`）在真实记录上的验证。

### 5.2 Europe PMC / PubMed Central

- **源**：Europe PMC 与 PMC（生物医学文献聚合与开放库存档）。用途：生物医学领域
  NPL 正文候选。
- **条款**：**未核实**。离线未访问；仓库无既有记载。注意 PMC 内**单篇条目**的
  许可彼此不同（这是常识风险提示，不是条款断言）——逐篇许可核查是升级前置之一。
- **再分发**：未核实 ⇒ 默认禁止再分发抓取内容。
- **正文获取**：未核实 ⇒ planned。
- **结论**：`support_level=planned`、不可执行。

### 5.3 OpenAlex / Unpaywall（发现服务）

- **源**：OpenAlex、Unpaywall。用途：按 DOI 查询开放获取副本**线索**（哪个版本、
  何处有副本），为全文链路提供候选 URL。
- **条款**：**未核实**。离线未访问；仓库无既有记载。
- **再分发**：未核实 ⇒ 默认禁止再分发。
- **正文获取**：发现服务本身不产正文；但它输出的 URL 指向的正文仍受目标源条款约束
  ——**发现许可 ≠ 全文许可**，下游抓取照样过本门。
- **结论**：`support_level=planned`、不可执行（元数据查询同样不执行，直到条款核实）。

### 5.4 出版商直连（DOI resolver → 出版商站点）

- **源**：经 DOI 解析落到各出版商站点的正文候选。**逐站条款彼此不同**，本文不对
  任何一家做概括性断言。
- **条款**：**未核实**（每一家都需要 §6 的独立取证）。
- **再分发**：未核实 ⇒ 默认禁止；在逐站取证前，默认假设自动化抓取不被允许——
  宁可拒绝，不可默许。
- **正文获取**：未核实 ⇒ planned。
- **结论**：`support_level=planned`、不可执行。升级必须逐出版商登记，禁止
  「一类站点」打包登记。

### 5.5 标准文本（ISO/IEC/IEEE/GB 等）

- **源**：各标准组织发布的标准全文。用途：标准资料证据链（蓝图 41B-1 的「标准」半边）。
- **条款**：**未核实**。标准文本的版权与授权销售条款按各标准组织规定，本仓库未核实
  任何一家；本文不概括、不臆测。逐家登记前不得代码抓取。
- **再分发**：未核实 ⇒ 默认禁止。标准全文工件即使人工合规获取（购买副本/官方授权），
  也只落本地工作区 raw/ 并绑定哈希，**永不入发行包**。
- **正文获取**：planned。取证前的合规通道是**人工**：证据链中标准引用仅允许书目级
  信息（标准号 + 名称 + 年份 + 条款号定位），正文内容由人工以合规渠道取得后按
  raw/ 纪律落盘（人工导入路径，同 `source-capabilities.md` 的 manual export 行）。
- **结论**：`support_level=planned`、不可执行；逐家取证后按 §6 升级。

## 6. 升级流程（planned → partial/full，四件套缺一不可）

1. **取证**：在本文对应源节补「实测记录」——取证日期、访问通道、条款原文锚点
   （URL/页面快照路径），格式照 `retrieval-evaluation.md` 附录 A.1；条款要点
   逐条摘录，不做转述性概括。
2. **登记**：`docs/policy-log.md`「在线来源接入事件」节记一行（授权状态、请求量、
   能力等级结论）。
3. **镜像同步**：`docs/architecture/source-capabilities.md` 表加/改该源行。
4. **代码同步**：本文 §4 总表与 `npl.py` `DOC_LICENSE_TABLE` 同一 commit 更新，
   `support_level` 改为 `partial`（契约测试过）或 `full`（真实联调过）。
