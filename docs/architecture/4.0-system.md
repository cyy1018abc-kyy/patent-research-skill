## 2. 写入权矩阵（ADR 0001 的执行细则）

| 位置 | 内核 | 扩展 | 说明 |
|---|---|---|---|
| `00_methodology/`、`01_search_plan/query_library.yml` | 写 | **只读** | 查询草案进 sidecar，人工批准后走原 queryplan 流程 |
| `02_search_logs/*.log.json`、`02_search_logs/raw/` | 写 | **只读**；B-04 采集器经内核 ingest 契约落盘 | 扩展不直写日志；raw 工件+日志由内核命令产生 |
| `03_candidates/` | 写 | **只读** | 扩展永不写候选、永不设 evidence_level |
| `04..07_*/` | 写 | **只读** | 判断与结论归内核与人工 |
| `workspace.yml` | 写 | **只读** | sidecar 绑定关系记录在扩展自己的 manifest |
| `<state_dir>`（默认 `.patent-intel/`） | 不感知 | **唯一写入区** | 删除即完全卸载，内核校验结果不变（ADR 0002） |

机器校验：`tests/test_kernel_boundary.py` 断言 (a) 扩展源码不出现对内核路径的写操作，
(b) `kernel_bridge.py` 只允许 `kernel_allowlist.READONLY_VERBS` 里的内核动词、拒绝
`FORBIDDEN_FLAGS` 全部写入型旗标。新增动词必须先补证明其只读的测试。

## 3. 数据流（一条候选证据的完整旅程）

1. Discovery 确认发明点 → glossary 轴（内核真值）。
2. `patent_intel query plan` 从轴生成 QuerySpec **proposal**（sidecar 内，`approved=false`）。
3. 人工逐条审批 → `approved=true` 后才可由内核 `queryplan`/原检索流程采纳进查询库。
4. 受控采集（WP-B）：原始响应先落 raw 工件（SHA-256 绑定）→ SearchRun 记录
   `hits_reported` 与 `records_fetched` 分离、`complete` 如实。
5. 归一化索引（PatentRecord）只作检索辅助；要成为内核 `verified` 候选必须经
   内核 `ingest` 从 raw 建档——扩展没有旁路。
6. WP-C 解析出 DocumentAnchor（哈希+页坐标+解析器版本）；不可核验的锚点只能辅助检索。
7. WP-D 证据投影与 claim chart 全部是 proposal（`requires_human_review` 恒为 true），
   生效路径只有内核 `draft`/`revise` 门禁 + 人工确认（V038 流程不变）。

## 4. 三 Skill 触发边界

| Skill | 触发方式 | 缺扩展时 |
|---|---|---|
| discovery | 无自动触发；`references/04-research-feedback.md` 指导何时建议用户跑 recall | 原流程不变 |
| research | `scripts/recall.py --help` 可用时给增强流程；不可用时打印安装指引并退出 3 | 原流程不变 |
| drafting | `references/18-evidence-advisor.md` 引导把建议当材料复核；扩展不进签核链 | 原流程不变 |

统一约束（O-02 验收）：evals 话术不把扩展能力说成内核能力；扩展未安装时三个 Skill
的既有意图路由零变化。

## 5. 失败与降级

- 内核缺失/协议不符：桥接函数抛 `KernelNotAvailableError`/`KernelCompatError`，CLI 退出 3。
- 工作区缺失：退出 2，提示 `--root`/`PATENTKIT_WORKSPACE`（与内核口径一致）。
- 网络默认关闭：任何联网命令需要配置允许来源 + 命令行 `--confirm-network` 双条件。
- 断点恢复：SearchRun 状态机 + checkpoint（B-04/B-05），恢复不覆盖已有 raw 工件。

## 6. 版本与兼容

- 扩展独立版本（wheel `patent-intel`），不与 skill 版本配对，避免发布联动膨胀。
- 内核兼容下限 `patentkit >= 0.8.0` 且 assessment protocol = 1（`kernel_bridge.kernel_info`）。
- 记录 schema：`schema_version` 整数、单调递增；读取方拒绝更新的 major，
  未知字段保留回传（前向兼容）。
