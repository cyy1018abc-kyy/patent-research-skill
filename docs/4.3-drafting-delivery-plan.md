## 1. 里程碑（按优先级）

### M1 实用新型基础（本轮，4.3.0 主体）

目标：实用新型申请能走通 D1→D8 全线，并且**按实用新型规则被拦截**，不会被当成发明处理。

| 项 | 内容 | 验收 |
|---|---|---|
| M1-1 数据模型 | `drafting_plan.application_type ∈ {invention, utility_model}`（可选，缺省按 invention，向后兼容，schema_version 仍 1.0）；`claim.claim_category ∈ {product, method, use}`（可选） | 旧工作区零迁移通过校验；契约测试 |
| M1-2 计划生成 | `draft plan --type utility_model`：附图需求改为「产品形状/构造示意图」，不生成方法流程图需求；实施例要求写明结构与连接关系 | 计划测试 |
| M1-3 G-D 审计码 | 实用新型专用：方法/用途类权项 → error；计划未声明附图需求 → error；只有流程图/状态机而无结构类附图 → error；权项正文出现方法/材料改进措辞 → warn（启发式，人工判断）；发明类型下独立权项未声明类别 → 不报（向后兼容） | 每个审计码都有正例和反例测试 |
| M1-4 交付门 | 实用新型交付无附图 → error（发明仍是 W-001 warn）；交付模型冻结 `application_type`；DOCX 标题按类型写「实用新型名称」/「发明名称」 | delivery 测试 |
| M1-5 外部附图登记 | 实用新型附图多为机械结构图，自动框图画不出来：新增 `figures import`——登记外部线条图（PNG/SVG），记录 SHA-256 + 附图标记清单 + 人工确认，交付时按哈希冻结 | 导入、确认、哈希失效测试 |
| M1-6 方法论 | `drafting/references/20-utility-model.md`（中英镜像）；SKILL.md 接线；evals 用例 | 术语一致性检查、链接检查绿 |

### M2 正文一致性校验（`draft lint`）

段落逐号比对；权项引用语 ↔ 结构；先行基础启发式；清楚性禁语；摘要 ≤300 字、名称字数；说明书五部分标题；附图说明覆盖每一幅图；附图标记括注与 `mark_mapping` 一致。error 级结果纳入 `deliver check`。

### M3 正文骨架（`draft render`）

由结构化权项和原子生成 `claims.md` 骨架（自动写引用语、按类型写主题名称）；生成说明书五部分骨架、段落编号，以及来自附图规格的附图说明。需要写实质内容的位置留成显式空槽，空槽未填不能过门。

### M4 申请文件书式 DOCX v2

拆成五个部分：权利要求书、说明书、说明书摘要、摘要附图、说明书附图。加分页和页码，附图每页一幅。书式参数要先查官方出处、登记后再写进代码，未核实的一律标注「审阅稿」。

### M0（贯穿）撰写基准

合成用例，按缺陷注入设计（含实用新型专用缺陷：方法权项、缺附图、只有流程图）。评分器衡量检出率和误报率，金标准答案必须满分，并做受控破坏测试。M1 用到的实用新型用例随 M1 一起交付。

### 后续

M5 OA 答复结构化（意见拆条、修改超范围核查、修改对照页）→ M6 CNIPA 官方格式调研（需要在维护者本机用官方工具验证）。

## 2. 法规口径登记原则

- 只写能给出出处的规则；条款号在 2023 年《实施细则》修订后变动过，**代码与文档只引用能核对的出处**，
  核对不了的标注「出处待人工核对」，不臆造条号。
- 本轮依据：专利法第 2 条第 3 款（实用新型 = 对产品的形状、构造或者其结合所提出的适于实用的新的技术方案）；
  《专利审查指南》第一部分第二章（实用新型专利申请的初步审查）。
- 启发式检查（措辞类）一律 warn，并要求人工判断，不得由工具自动下结论。
