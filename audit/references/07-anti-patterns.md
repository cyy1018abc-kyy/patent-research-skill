# 07 — 反模式（full audit 与 guidance 通用）

> 改编自原件 Anti-patterns（10 条），按专利检索域改写并补 2 条领域特有项。
> 每条都对应校验器或协议里的一处硬门。

1. **把检查清单当审计**：跑完固定动作 ≠ 覆盖；没有台账单元与 checks 的「我查过了」
   不是覆盖证据。（硬门：台账即覆盖主张）
2. **叙事性覆盖声明**：「主要数据源都覆盖了」「分类号面基本扫过」这类散文，
   不进 REPORT；覆盖只认单元状态。
3. **相邻段落冒充定位**：引文在 [0005]，要素依据在 [0004]，引用 [0005] 撑要素
   ——定位漂移，A5 必退。（硬门：locator 命中 + quote 逐字）
4. **意译当引文**：把原文改写几个字再「加引号」；或把两段各半句拼成一条引文。
   （硬门：quote 逐字校验）
5. **needs_validation 当低置信 confirmed 用**：没有确切缺失事实、没有可执行
   核验计划的「待验证」是伪装的结论。（硬门：blockers ≥1 + validation_plan）
6. **给待验证结论标影响类目**：X/Y/A 只属于 confirmed。（硬门：字段禁集）
7. **破坏性与确定性互相折算**：「我确定它破坏新颖性」不是 X 的理由；
   「只是背景文献」不自动降低确定性。两轴分开评，理由分开写。
8. **提出者自证 confirmed**：没有独立证伪/独立复核轮次的 confirmed 是协议违规。
   （硬门：independent_review 必填；A3/A5 角色隔离）
9. **部分披露报成 full**：区别特征没找齐就把披露程度写成 full，进而虚标 X。
   （硬门：partial 禁 X；distinctions 与原文比对）
10. **旧审计结果当当前覆盖**：旧 run 的 confirmed 不重验就沿用；旧 needs_validation
    不转当前工作。（硬门：prior_status 规则 + 携带必过独立验证）
11. **prose 候选**：狩猎产物没有四件套（对比文件/定位/逐字引文/披露程度）就当
    候选登记。（硬门：candidate 需 fingerprints + checks 证据）
12. **审计越权**：审计顺手补检索、改候选、跑 --apply，或把报告当法律意见。
    审计只读工作区、只写 12_audit/，建议只进报告。（硬门：写隔离 + 中立性规则）
