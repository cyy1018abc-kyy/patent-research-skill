# 02 — 阶段 A2：覆盖率狩猎与批评家

> 对应原件 HUNTING 的覆盖率狩猎波次；「攻击类」换成「检索策略类」，
> 狩猎产物从漏洞候选换成「要素↔对比文件」映射候选 + 覆盖事实。

## 1. 狩猎者提示词（每单元认领时逐字使用，`<>` 处填值）

```text
你是本次审计的检索狩猎者。认领台账单元 <coverage_id>：
要素 <element>，数据源 <source>，分类号 <klass>。
只允许：读工作区 <starting_paths> 与其引用的语料；执行该单元承诺的检索/复核。
不允许：跳到其他单元；修改工作区；把「没有命中」写成「没有相关文献」。
步骤：
1. 执行该单元承诺的检索（或复核既有日志），逐条记录 checks；
2. 对每条命中，判断它披露了要素的哪些特征（full/partial/absent），
   候选映射必须给：对比文件标识 + 段落定位 + 逐字引文 + 披露程度初判；
3. 覆盖了该单元的全部承诺后置 covered；发现潜在映射置 candidate 并登记
   result_fingerprints；被源缺失/权限阻塞置 blocked 并写明阻塞点。
返回结构化结果（无散文包裹）：单元更新 + checks + 候选映射列表。
```

**候选门槛**：没有「对比文件 + 定位 + 逐字引文 + 披露程度」四件套的命中只是一条
日志，不是候选映射。宁可 covered 无候选，不可 prose 候选。

## 2. 波次与批评家

1. 按台账优先级分派单元（改源重验 > 旧缺口 > 新单元），一轮为一个 wave；
2. 每波后**必跑批评家**：审视台账与 checks，回答三类问题——
   - 哪些单元只是形式 covered（checks 泛泛、没有具体检索式/文档）？
   - 要素×源×分类号矩阵还有哪些**缺格**（漏播种）？
   - 候选集合里哪些映射互相矛盾或与既有结论冲突？
3. 批评家提议的重派：先归档 attempts（带 `reassignment_reason`），再 wave+1
   新认领；quick profile 只允许 1 波 + 1 次批评家，发现的重派记 `deferred`。

## 3. 检索策略类（替代原件攻击类的「 hunting 视角」，逐单元选贴）

- **词法面**：同义词/上位词/竞品术语是否都试过？中英双语是否都试过？
- **分类面**：初判分类号的邻域（上位组、相近下位）是否覆盖？
- **引证面**：命中文献的引证链（向前/向后）是否走过？
- **同族面**：关键命中的同族/优先权链是否查过（公开日与内容可能不同）？
- **否定面**：结构化检索有没有反着验证过——「如果这篇文献披露了要素，
  我会在哪条检索式里遇到它」？答不上来说明检索式有盲区。

选贴规则：单元按其要素/源/分类号选择适用的策略类并记录在 checks 的
description；不适用也要记 excluded 及原因（与原件 companion/excluded 纪律同构）。

## 4. 汇总与台账更新

规划者是唯一写入者：按 §00 协议 §6 的状态机更新单元；把每条候选映射按
`MAP:<element-ref>:<对比文件标识>` 预赋 fingerprint（同一根因跨状态稳定）。
台账更新后重跑 `validate_ledger.py`。

## 5. 单 agent 模式的轮次记账

每轮 = 一次单元认领或一次批评家。预算按 `00-audit-protocol.md` §7 预留与扣减；
`run-metadata.json` 的 `budget` 字段记录 spent/planned。
