# 06 撰写与润色规范

## 稿件放在库外（硬要求）

**稿件正文不进仓库**。仓库里只放：

- 路径 + `sha256`（`07_撰写/稿件登记.yml`）
- 版次台账（`07_撰写/版次台账.md`）
- 特征原子表、支持映射表（结构化的分析产物）

**原因**：稿件是最容易泄露的资产，而仓库要能分发（见 `04-证据等级制度.md` 的"内核与数据分离"）。

## 每次改稿的固定动作

```powershell
# 1. 改完稿，重新绑定 sha256
python -m patentkit attest --apply

# 2. 在 07_撰写/版次台账.md 加一行（版本 / 日期 / 改了什么）

# 3. 校验登记表结构
python -m patentkit validate --strict
```

> 忘了 `attest --apply`，`attest --check` 会报 sha256 漂移（exit 1）——
> 这是好事，说明"登记表指的文件"和"实际文件"不一致，评审可能看的是旧版。

## 权利要求的三条自查

### 1. 数值范围必须被说明书支持（最容易漏）

**实审中会被直接指出「得不到说明书支持」，且通常无法通过答复补正**（补入新数值属新增内容）。

核对方法（本项目已工具化，产出 `07_撰写/权利要求/数值一致性核对.md`）：

1. 把权项里每个「数值范围」抽出来
2. 逐个查说明书有没有
3. 特别查**同一参数的矛盾范围** —— 权项比说明书宽 = 超范围

三类缺陷及其严重性：

| 缺陷 | 例 | 严重性 |
|---|---|---|
| **超范围**（权项比说明书宽） | 权项 `R_c ∈ 2~6`，说明书 `3.0~5.0` | **最危险**，无法补救 |
| 边界未披露 | 权项 `0.33~0.45`，说明书只有 0.36 | 中 |
| 零依据 | 权项 `λ ∈ 1.05~1.35`，说明书全文无取值 | 中 |

**修法二选一**：收窄权项到已公开范围（安全），或申请日前补说明书（只能补通用说明与典型值，不能新增技术方案）。

> ⚠️ 这个判断**必须由发明人做** —— 能不能补，取决于该范围是否已有仿真/实验支撑。

### 2. 每条权项都要能映射到说明书段落

维护 `07_撰写/说明书/支持映射表.md`，逐原子标出支持段落。
标不出来的原子，要么补实施例，要么删。

### 3. 不能有孤儿权项

每个从权都必须依附于某个独立权项，且其附加特征不能和依附对象矛盾。

## 有益效果必须可追溯

`G-D-01` 的硬要求：**每条有益效果都能对应到 `04_对比分析` 里某个 D 列的差异**。

对不上 D 列的效果，要么是没做对比，要么是效果本身站不住。

| 合格 | 不合格 |
|---|---|
| 「分级排放使氧排放损失 1.86→0.44 mol/600s（-77%）」 | 「提高效率」 |
| 「负载阶跃供氧响应 0.19→0.05 s（3.8×）」 | 「响应更快」 |

## 公式渲染

| 错 | 对 | 原因 |
|---|---|---|
| `n_{in}^{hat}` | `\hat{n}_{in}` | 上标里写字会渲染成字面 "hat" |
| 裸 `%` | `%%`（在部分工具的参数解析里） | 被当成格式符 |

改完公式要**逐个预览**，不能只看源码。
