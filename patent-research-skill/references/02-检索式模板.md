# 02 检索式模板

## 硬规则

1. **主检索式最多 3 个 AND 子式** —— 再多命中数会塌到个位数。
2. **IPC 作后置筛选**，不要写进检索式。
3. **每个子查询要窄**。因为 CNIPA 每次只返回 3 条，宽查询等于浪费一次机会。
4. **子查询之间要有角度差异**，不要同义改写凑数。

## 一条合格子查询的样子

```
{ label: 简名, abstract: 关键词A and 关键词B and 关键词C }
```

三个词的组合原则：**领域词 × 对象词 × 手段词**

| 位置 | 作用 | 例（燃料电池 / 气液分离） |
|---|---|---|
| 领域词 | 限定技术领域 | 燃料电池 |
| 对象词 | 限定作用对象 | 气液分离 / 排水 / 排放 |
| 手段词 | 限定实现方式 | 毛细 / 分级 / 双阈值 |

## 反例与正例

| 反例 | 问题 | 正例 |
|---|---|---|
| `燃料电池 and 控制` | 太宽，3 条全是无关 | `补氧 and 燃料电池 and 前馈` |
| `燃料电池` | 无对象无手段 | `死端 and 阳极 and 燃料电池` |
| `燃料电池 and 燃料电池 and 燃料电池` | 同词重复 | 无意义，删掉 |
| `(A or B) and C and D and E` | 超 3 个 AND | 拆成多条子查询 |

## 子查询怎么攒

一个轴通常需要 **10–28 条**子查询才能把池子撑到可判的规模。攒法：

1. **从轴的每个技术特征出发**，各写 1–2 条
2. **从同义词族出发**：中文 / 英文 / 缩写 / 旧称
3. **从应用场景出发**：车载 / 航空 / 航天 / 船用 / 固定式
4. **补漏专题**：把已判候选里反复出现的词补成新子查询

## 判断"检索够了没有"

不要凭感觉。看两个数：

| 指标 | 含义 | 达标线 |
|---|---|---|
| **每轴 relevance≥4 篇数** | 该轴的有效覆盖 | ≥10，且**缓冲 ≥+3** |
| **池子是否已 100% 判完** | 还有没有可判的 | 判完了才说明"不是判得不够，是检索得不够" |

> **缓冲为什么重要**：门槛刚好卡在 10 的时候，一次改判或一次剔除就会让门禁翻红。
> 曾出现"建了缓冲又被自己的复核推翻"—— 因为缓冲建在了误判上。

## 与工具的关系

```powershell
# 看某轴的子查询计划
python -m patentkit search-plan --axis N1

# 只跑新增的子查询（原有日志不会被撞名）
python -m patentkit fetch-cnipa --axis N1 --from-library --only 18,19,20
```

子查询登记在 `01_检索方案/检索式库.yml` 的 `cnipa_batches` 下，
**追加在末尾、不改原有序号** —— 否则历史日志会对不上。
