# 05 验收门口径

> **判据已代码化**：`patentkit/gates.py`，用 `python -m patentkit gates` 计算。
> 每门按三个证据等级各算一次，**PASS 只认最严的 `verified` 列**（见 `04-证据等级制度.md`）。

## 五门判据

| 门 | 判据 | 门槛 |
|---|---|---|
| **G-S-01** | 阶段 1 候选清单 | **≥200 条专利 + ≥200 条文献**（按 `kind` 计数） |
| **G-S-02** | 阶段 2 主轴覆盖 | **每轴 ≥10 篇** `relevance≥4`；`role=excluded` 不计 |
| **G-S-03** | 阶段 3 近端对比文件 | **≥5 篇** `role=near_prior_art` |
| **G-S-04** | 同族与被引完整 | `role ∈ {near_prior_art, family}` 的 `family` 与 `cited_by` **均为数组且非空** |
| **G-S-05** | 可回放 | `capture_mode=live` 且 `raw/` 产物存在且非空 **100%** |

## 两处历史口径修正（原判据有错）

1. **G-S-03** 原写「`novelty_check = blocking` 计数 ≥ 5」—— **错**。
   `blocking`（是否阻挡新颖性）与"近端对比文件数量"是两个不同语义。
   改用 `role=near_prior_art` 计数，两者解耦。

2. **G-S-04** 原硬编码"既有专利 1、专利 2"—— **不可泛化**。
   已改为引用目标专利自身的对比文件集合。

## G-S-02 的缓冲纪律

`G-S-02` 是最容易"刚好达标然后翻红"的一门。

| 状态 | 含义 | 行动 |
|---|---|---|
| 某轴 ≥4 篇数 = 10 | 零缓冲，一次改判就 FAIL | **必须补检索** |
| 某轴 = 11~12 | 缓冲 +1~+2，仍然脆 | 建议补到 +3 |
| 某轴 ≥ 13 | 缓冲 +3 以上 | 安全 |

**怎么补**：先看该轴池子是否 100% 判完 —— 判完了说明不是"判得不够"而是"检索得不够"，只能补子查询。

## validate 与 gates 的区别

| | 管什么 | 失败后果 |
|---|---|---|
| `validate` | **数据结构一致性**（V001–V028） | 有 `error` → exit 1 |
| `gates` | **验收门**（5 门 × 3 列） | 有门非 PASS → exit 2 |

两者都要过。CI 入口是 `python -m patentkit check`（= `validate --strict` + `gates --quiet`）。

## 几条常见 FAIL 的原因对照

| 现象 | 原因 | 修法 |
|---|---|---|
| G-S-01 文献侧 0 | 只做了专利检索 | 用 `fetch-crossref` 补文献 |
| G-S-02 某轴 9 篇 | 池已判完 | 补子查询，不是重新判 |
| G-S-03 N/A | `role` 全为 `pool` | 从 `relevance≥4` 里挑出近端 |
| G-S-04 N/A | 同上（无 `near_prior_art`） | 同上 |
| G-S-05 <100% | 有日志缺 `raw/` | 重跑该次检索 |
| `validate` 报 V018 | `near_prior_art` 未进任何 run | 跑 `patentkit report <TGT-ID>` |
