# 03 三层判定

## relevance 是**两维**的

这是本项目最重要的一条口径。`relevance` 不是单一分数，而是两个维度的合成：

```
relevance = min(relevance_problem, relevance_means)
```

| 维度 | 问什么 | 为什么必须分开 |
|---|---|---|
| **技术问题**（`判问题`） | 它解决的问题和本发明重合多少？ | 问题不同 → 手段再像也不构成对比 |
| **技术手段**（`判手段`） | 它的实现方式和本发明重合多少？ | 手段不同 → 问题再像也不能否定新颖性 |

**取 `min` 而不是平均**：两维都够格才算够格。技术问题不同的文献，
就算技术手段一模一样，也救不回来 —— 反之亦然。

### 1–5 级定义

| 分 | 技术问题 | 技术手段 |
|---|---|---|
| 5 | 完全相同 | 完全相同 |
| 4 | 相同，仅应用场景不同 | 主要手段相同，个别环节不同 |
| 3 | 同领域不同子问题（**默认值**） | 同类别不同实现 |
| 2 | 相关领域 | 仅原理相通 |
| 1 | 无关 | 无关 |

> **`3` 是入库默认值**，意为"尚未判定"。判过之后必须写 `reviewed_at`，
> 否则会被当成未判。

## 三个 `role`

| role | 含义 | 进哪个门 |
|---|---|---|
| `near_prior_art` | 进入 D 列的近端对比文件 | `G-S-03`、`G-S-04` |

## 三层判定框架

### 第一层：单篇新颖性

问：**有没有一篇单独披露了本发明的全部核心技术特征？**

| `novelty_check` | 含义 |
|---|---|
| `blocking` | 单篇即覆盖全部核心特征 → **新颖性不成立** |
| `covered` | 覆盖某一权利要求的全部特征，但未覆盖整体 |
| `partial` | 只披露部分特征（多数落这里） |
| `untouched` | 未披露任何特征 / 与技术主题无关 |

**判法**：对每篇问"这一篇单独读，能不能看出本发明的 N 条技术轴"。
**只有当一篇同时披露所有轴的核心手段才叫 `blocking`** —— 这极难，正是发明的价值所在。

### 第二层：组合创造性

问：**把 2–3 篇组合起来，是否使本发明显而易见？**

**这一层比第一层更危险**：审查员最爱用「D1 + D2 结合」。
做法不是找最弱的组合，而是**主动找自己方案的最强组合**。

**最强的论证结构**：找出**零披露原子** —— 即所有对比文件加起来都拼不出的特征。
组合的前提是每个成员至少贡献一个特征；贡献不了的原子，组合也造不出来。

**必须自我攻击**：列出审查员最可能的反驳及应对。
不写这段，结论就是自欺。

### 第三层：技术效果

问：**是否存在非显而易见的技术效果？**

判据：该效果是否必须以本发明的区别特征为前提？缺该特征是否**在原理上不可能**达到？

| 有效 | 无效 |
|---|---|
| 「分级排放使氧排放损失 1.86→0.44 mol/600s（-77%）」 | 「提高效率」「更安全」 |
| 「μG 下阴极压降达 1g 的 5.2 倍」 | 无数据的定性描述 |

> ⚠️ 若数据来自仿真，必须在说明书标明仿真条件，否则会被质疑可复现性。

## 工作流

```powershell
# 1. 看进度
python -m patentkit review progress

# 2. 导出待判（有摘要的才判得动）
python -m patentkit review export --unreviewed --with-abstract --axis N4 --out 表.csv

# 3. 人在 Excel 里填 判问题 / 判手段（其余列留空）
#    注意：中文 Windows 的 Excel 会把 CSV 存成 GBK 且去掉 BOM —— 工具已自动识别

# 4. 先 dry-run 看影响，确认后写盘
python -m patentkit review apply 表.csv
python -m patentkit review apply 表.csv --apply
```

> `apply` 是 **fail-closed**：任何一行有非法值，**一个字都不写**。
> 这是刻意的 —— 曾经半途失败留下过部分写入的脏状态。
