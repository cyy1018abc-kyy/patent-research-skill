# 09 交底书与申请文件底稿

> 定位：把检索成果转化为**交底书/申请文件底稿**。对标 patent-disclosure-skill 的
> patent-disclosure / patent-application 与 cnipa-patent-kit 的 drafting-spec。
> **本技能产出底稿并标注缺口，不替代专利代理师，不构成法律意见。**

## 前置条件（不满足就不开工）

- 五项验收门中 **G-S-01～G-S-03 至少达标**（否则交底书建立在检索不足之上）；
- 对比矩阵已填，D 列每篇有证据等级与判定状态；
- 数值声明溯源（A/B/C）已登记（见 [00 前置纪律](00-prerequisites.md)与 `patentkit provenance check`）。

## 交底书五段式骨架（发明/实用新型）

1. **发明名称**：≤25 字，主题类型明确（装置/方法/系统）；
2. **技术领域**：一段，写上位领域 + 细分；
3. **背景技术**：**只写检索到的真实文献**——引 D 列编号（P-xxx）+ 文献号 + 缺陷。
   每条缺陷必须对应对比矩阵里的差异点；**禁止编造「现有技术存在……问题」**；
4. **发明内容**：要解决的技术问题（对应三层判定第二层的区别特征）+ 技术方案
   （按 N 轴逐条，可直接复用特征原子表）+ 有益效果（每条映射 D 列差异，量化优先）；
5. **附图说明 + 具体实施方式**：至少一个完整实施例；数值来自溯源登记的 A/C 级，
   C 级必须显式标注「示例值」。

## 从交底书到申请文件（细则 20–23 落地）

| 文件 | 依据 | 自检 |
|---|---|---|
| 权利要求书 | 细则 20-22：独立/从属结构、单一性 | 走 [10](10-claim-drafting.md) 的层次自检 |
| 说明书 | 细则 20：五部分结构（技术领域/背景/内容/附图/实施方式） | 每条权项有支持段落（support_mapping_table） |
| 摘要 | ≤300 字，写清主题与效果 | 字数与范围声明自检 |
| 附图 | 见 `patentkit figures`（research 技能 08 号文档有完整规范） | 标记双向一致（V033） |

产出全部放 `07_drafting/`（稿件正文在库外，只留 registry 与台账）。

## 说得清 / 说不清

写不下去的地方**不要编**：记入 `07_drafting/open_questions.md`（问题、缺什么材料、找谁补）。
「说不清」清单是交底书的一部分——交给代理师时一并交，比藏在正文里强。

## 与工具的衔接

```powershell
patentkit ledger                 # 写背景技术前先对账：只引用账本内的编号（V034）
patentkit export-docx <TGT>     # 检索报告 docx（交底书附件）
patentkit provenance check      # 数值来源全绿再进实施例
```

## 边界（硬性）

- 本流程**不判断可专利性、不预测授权**；
- 撰写正文前先确认检索侧门禁达标（见 [00 前置纪律](00-prerequisites.md)）：跳过对比直接写 = 把风险写进权利要求；
- 侵权分析、软著联动**默认不做**（决策记录见仓库 `docs/scope-decisions.md`）。
