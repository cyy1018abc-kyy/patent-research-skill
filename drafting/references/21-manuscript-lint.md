# 21 · 正文一致性校验（`draft lint`，4.3 / M2）

> 结构化管线（14/15 号）校验的是**模型**（原子、权项、支持映射）；本文件定义对**稿件正文**
> （`07_drafting/manuscript/{claims,specification,abstract}.md`）的机器检查：正文与结构化模型是否一致、
> 是否符合撰写的形式要求。error 级发现阻塞交付（`deliver build` 拒绝，`deliver check` 报 E-016）；
> 启发式检查一律 warn，由人判断。本工具不判断授权前景，不替代代理师复核。

## 1. 命令

```powershell
python -m patentkit draft lint --root .\workspace          # 人读报告（M-001…M-016）
python -m patentkit draft lint --root .\workspace --json   # 机器可读
```

稿件尚未写时只报一条 M-001 warn，不阻塞任何门。

## 2. 校验码

| 代码 | 级别 | 含义 | 依据 |
|---|---|---|---|
| M-001 | error | 稿件文件缺失、无编号权项/段落、摘要为空 | 交付输入约定（17 号） |
| M-002 | error | `claims.md` 编号重复/不连续，或与结构化权项编号集合不一致 | 结构化模型（15 号） |
| M-003 | error/warn | 从属权项正文没有引用语、引用的不是结构化父项、引用不存在或在后的权项（error）；多项引用而结构只记一个父项（warn） | 权项引用关系须与结构一致 |
| M-004 | error/warn | 段落号重复（error）；未从 `[0001]` 连续编号（warn） | 说明书段落编号惯例 |
| M-005 | warn | 说明书五部分标题（技术领域 / 背景技术 / 发明内容或实用新型内容 / 附图说明 / 具体实施方式）缺失或顺序不对；无附图时不要求「附图说明」 | 实施细则说明书条款（条号以官方现行文本为准） |
| M-006 | error | 摘要超过 300 字（不计空白） | 实施细则说明书摘要条款 |
| M-007 | warn | 名称超过 25 字（一般要求） | 审查指南第二部分第二章 |
| M-008 | warn | 权项含糊用语：约/大约/接近 + 数值、数值 + 左右、例如、最好是、尤其是、必要时、类似物、优选、等 | 审查指南第二部分第二章（权利要求清楚） |
| M-009 | warn | 先行基础启发式：「所述X」在本权项此前或其所引权项中没有出现过 X | 撰写惯例；启发式，可能误报 |
| M-010 | warn | 权项中的附图标记未置于括号内（如「壳体1」应写「壳体(1)」） | 实施细则权利要求书条款 |
| M-011 | error | 部件名称与附图标记的对应和附图规格（`mark_mapping`）不符（权项或说明书） | 附图标记全文一致 |
| M-012 | warn | 主题词或内容标题与申请类型不符（实用新型稿写「本发明」「发明内容」，或反之） | 20 号文档 |
| M-013 | error | 有附图规格但说明书（有「附图说明」部分时限定在该部分）未描述该图；或正文引用了没有附图规格的图 | 实施细则说明书条款 |
| M-014 | warn | 权项中使用「如图…所示」「如说明书…」 | 实施细则权利要求书条款（除绝对必要外不得使用） |
| M-015 | error/warn | 一项权项在结尾之外使用句号（error）；结尾没有句号（warn） | 审查指南第二部分第二章（每项权利要求只允许在结尾使用句号） |
| M-016 | error | 正文仍有 `draft render` 留下的 `【待补：…】` 空槽 | [22 号](22-manuscript-render.md)：骨架未填完不得交付 |

> 法规口径只写到能核对的层级（法律/细则条款名、指南章节）；2023 年细则修订后条号有变动，
> 本文件**不臆造条号**，需要引用时以官方现行文本核对并登记 `docs/policy-log.md`。

## 3. 写稿约定（让 lint 读得懂）

- 权项：每项一段，以 `1. ` 开头；从属权项写「根据权利要求N所述的……」，N 与结构化 `parent_claim_no` 一致；
  附图标记用括号：`壳体(1)`。
- 说明书：五部分标题**独立成行**（可带 `#`）；段落以 `[0001]` 起头、连续编号；
  「附图说明」部分逐图写「图N为……」。
- 摘要：不超过 300 字；实用新型写「本实用新型」，发明写「本发明」。

## 4. 与交付门的关系

- `deliver build`：先按冻结模型做结构性拒绝（缺文件、编号、段落、图号），再跑 lint；有 error 即拒绝构建。
- `deliver check`：lint error 以 **E-016** 列出；签核后改稿使 lint 出错，同样回落交付状态。
- warn 级不阻塞，但交付前应逐条人工过一遍（尤其 M-009 先行基础与 M-008 含糊用语）。

## 5. 准确性证据

撰写正文一致性基准（`benchmarks/drafting/`，合成）：实用新型与发明各一份干净稿（必须零发现）和一份
缺陷注入稿；CI 以 `tools/score_drafting.py --gate perfect` 锁定「全部注入缺陷检出、零误报」。
基准只证明规则在合成稿上按设计工作，不代表对真实稿件零误报——启发式结果仍需人工判断。
