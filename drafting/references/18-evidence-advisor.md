# 18 · 证据顾问（patent_intel 扩展，可选）

> **边界先行**：证据顾问来自可选扩展 `patent_intel`。它产出的是**可复核的视图与
> 建议**：证据投影、覆盖矩阵、claim chart 草稿、修改提案。权项的修改与新颖性
> 结论仍只由内核规则（`draft audit` / `revise` / V038 人工确认）决定；扩展没有
> 「自动确认」后门，也不输出任何授权前景承诺。扩展未安装时 drafting 流程不变。

## 证据视图（`evidence build`）

```bash
python -m patent_intel evidence build --root <ws>
```

- 从内核候选只读重建 `特征 × 对比文件 × 证据` 投影；每格要么带
  `raw_sha256` 锚定，要么显式标 `no_evidence`——不存在"大概有据"的状态。
- 投影可随时删除重建（sidecar），删除前后内核 `check` 结果不变。
- **stale 纪律**：候选内容一变（指纹变），基于旧指纹的投影自动标
  `stale`，等待重审——已批准的视图不会跨内容变更悄悄存活。

## claim chart 草稿（库 API）

- 行=权项、列=对比文件；格内只放内核评审状态与"待人工逐特征映射"占位
  （TBD），扩展不做侵权/新颖性判定。
- **单篇 vs 组合**：没有单篇 blocking、却有 ≥2 篇 partial 时，输出的是
  「组合假设」提示（需要人工合并分析），**不是**"组合必然破坏创造性"的结论
  （UT-E02：两篇各披露部分特征 ≠ 单篇覆盖全部）。

## 修改提案（`advisory review`）

- 每条提案强制 `requires_human_review=true`，并写明它必须经过的内核门
  （`draft audit` + `revise` + 人工确认 V038）。
- 提案只引用工作区里真实存在的候选；支撑映射风险（修改是否有说明书支持）
  被标记为待人工判断（EX-02），扩展不代答。

## 使用纪律

1. 报告里的"无证据/未覆盖"只描述**当前检索样本**，永远不能当"查无现有技术"；
2. 投影是视图不是第二份内核真值——判断以内核候选与人工确认为准；
3. 把任何提案抄进底稿前，走完内核门禁，扩展输出只是材料。
