# 11 审查意见答复骨架

> 对标 patent-disclosure-skill 的 patent-oa（拆条款问答 + 答复稿）与 Claude-Patent-Creator
> 的「像审查员一样读权要」。**本流程产出答复底稿与证据回链，不构成法律意见；
> 期限由官方发文决定，先看 `patentkit deadlines` 台账再谈内容。**

## 第一步：拆条（每条意见一行）

收到 OA（第一次审查意见通常 4 个月答复，再次 2 个月——以发文日为准）后，把每条意见拆成：

| 条款 | 类型 | 涉及权项 | 引用对比文件 | 指称缺陷 |
|---|---|---|---|---|
| X1 | 新颖性（A22.2 类指称） | 权1 | D_oa1（审查员引的文献号） | 单篇覆盖全部特征 |
| X2 | 创造性（A22.3 类指称） | 权2-5 | D_oa1+D_oa2 | 结合显而易见 |
| X3 | 清楚/支持（A26.4 类指称） | 权3 | — | 术语/数值无支持 |

**先入账**：审查员引用的文献如果不在候选清单里，先补进 `03_candidates/`
（按 research 技能的检索式纪律补一条定向子查询 + 落 raw/），再进对比。
**证据账本之外的文献不参与答复论证（V034 同款纪律）。**

## 第二步：逐条回链（复用检索期资产）

每条 X 的答复骨架 = 三层判定的反向应用：

1. **特征对照**：权项特征 × 审查员文献，逐格填「披露/未披露」——直接复用
   `assets/blank_comparison_matrix.md` 的格式，每格引原文；
2. **论点选择**（按三层判定的框架）：
   - 单篇不覆盖全部特征 → 新颖性成立（找「零披露原子」）；
   - 组合缺结合动机 / 存在反向教导 → 创造性成立；
   - 技术效果必须以区别特征为前提 → 效果论据（引 D 列量化数据）；
3. **修改策略**（必要时）：
   - 把从属权项特征并入独权（先查 support_mapping_table 是否支持）；
   - 收窄数值范围（必须落在溯源登记 A 级范围内）；
   - 任何修改 → 走 [13-改稿闭环](13-revision-loop.md)，重新 `attest --apply` + 过门。

## 第三步：答复底稿结构

```
一、概述（同意/部分不同意/陈述意见）
二、修改说明（若有：改了哪几处，不得超范围）
三、逐条答复（每条 X 一个小节：指称 → 事实对照表 → 论证 → 结论）
四、结论（每项权项的当前状态）
```

## 工具衔接

```powershell
patentkit deadlines list             # 先看期限（以发文日为准）
patentkit ledger                     # 答复只引用账本内的证据
patentkit map <TGT>                 # 覆盖总览（给代理师看全局）
python -m patentkit provenance check # 若修改涉及数值
```

## 边界（硬性）

- **不预测授权结果，不写「必将授权」**；
- 意见指称的条款归类如不确定，标注「需代理师确认」，不要替审查员解释法条；
- 历史案件（脱敏后）可入 `04_comparative_analysis/runs/` 作对照参考，
  但**不得**把在审内容贴进任何公网客户端（保密边界见 README）。
