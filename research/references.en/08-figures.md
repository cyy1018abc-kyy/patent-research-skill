# 08 Figure requirements and figure-mark checks

> Benchmarked against cnipa-patent-kit's figure-drawing plus its two-way figure-mark
> check; implemented in `patentkit figures` (kernel 0.3.0).

## Hard requirements for Chinese patent drawings (cponline upload rules)

- **Black-and-white line drawings** only: no grayscale, no color, no photographs
  (photos may be appended after the specification only when necessary);
- **300 DPI** or higher resolution (render the deterministic SVG to a 300 DPI
  black-and-white bitmap before submission);
- Parts are marked with **Arabic-numeral reference signs (figure marks)** — 10, 20,
  31… — consistent across the whole application and the drawings;
- **No extra text inside a figure** (except necessary keywords, such as 是/否
  "yes/no" labels on flowcharts);
- The "图 1 / 图 2" (FIG. 1 / FIG. 2) numbering in the specification must match the
  order of the drawing pages.

## Two-way figure-mark consistency (V033)

The two most frequent failure modes; the tool intercepts them as **warn** (text
extraction is heuristic — it only reminds, never edits automatically):

1. The specification mentions reference sign **32**, but the figure only shows
   30 and 31 — a "clarity" problem under the Implementing Regulations;
2. The figure shows a part that the description never mentions — the reader cannot
   map text to figure.

```powershell
# Figure specs live in 07_drafting/figures/*.figure.yml:
# figure: FIG-1
# title: System block diagram
# parts:
#   - {id: "10", name: electrolyzer}
#   - {id: "20", name: separator}
# connections:
#   - {from: "10", to: "20", label: recycle stream}

python -m patentkit figures check      # two-way cross-check (V033 warn)
python -m patentkit figures draw FIG-1 # deterministic SVG block diagram (offline, dependency-free)
```

The SVG is vector-based and generated fully offline; convert it to a 300 DPI
black-and-white bitmap locally before submission (the kernel does not take on heavy
dependencies for this).

## Figure spec conventions

- One figure per `*.figure.yml`; the `figure` field is the figure ID (FIG-1…);
- `parts[].id` is the reference sign (a numeric string) and `name` is the part name;
- `connections[]` describes block-diagram arrows (`from`/`to` use reference-sign ids);
  `label` is optional;
- Hand-drawn complex structural drawings need not be generated by the tool, but the
  **spec file must still exist** — the check relies on the spec, not on the image.

## Boundaries

- V033 is a **warn**: the regex extraction of "part-name + number" can misfire (e.g.
  "step 3" does not match, but other scenarios might). Every warning must be
  re-checked by a human against the figure before acting; the rule never deletes a
  reference sign automatically.
- Figures are only one part of the working draft; **this is not legal advice** — have
  a patent agent review before filing.
